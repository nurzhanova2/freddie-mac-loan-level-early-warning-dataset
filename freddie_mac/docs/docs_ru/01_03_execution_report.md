# Выполнение этапов 1–3: подготовка основы датасета

**Статус на 14 сентября 2026 года:** этапы 1 и 3 выполнены для первой версии
проекта; этап 2 выполнен в части официальной схемы Release 47 и ожидает
валидации на аналитических файлах из Clarity.

## 1. Зафиксированный дизайн первой итерации

В качестве источника выбрана Standard Dataset Freddie Mac Single-Family
Loan-Level Dataset, Release 47 (июль 2026 года). Единицей наблюдения будет
«кредит–месяц наблюдения» (`loan_id × observation_month`). Исследуемая
совокупность ограничена отдельными ипотечными кредитами в сегменте US
single-family mortgages; она не представляет универсальный person-level
датасет заёмщиков.

На первой аналитической итерации будут использоваться связанные файлы
`sample_orig_YYYY.txt` и `sample_perf_YYYY.txt`, загруженные из Clarity Data
Intelligence. Зафиксированы горизонты раннего предупреждения 3 и 6 месяцев.
Для шестимесячной разметки дата наблюдения не должна быть позднее сентября
2025 года, если performance cutoff фактической выгрузки — март 2026 года.
Каждая конкретная выгрузка будет дополнительно проверена по её manifest до
создания меток.

Эти решения сохранены в
[`config/study_scope_v01.yml`](../../config/study_scope_v01.yml).

## 2. Проверка официальной схемы

В проект сохранены официальные документы Freddie Mac: General User Guide,
File Layout и File Headers, действующие с июля 2026 года. Из File Layout
автоматически сформирован машиночитаемый словарь
[`docs/data_dictionary_release_47.csv`](../../data_dictionary_release_47.csv).
Он содержит 31 поле origination-файла и 35 полей monthly performance-файла,
включая их позицию, технический формат и максимальную длину.

Доступность каждого monthly-поля для прогнозирования пока обозначена как
`review_required`. Окончательное решение будет внесено в leakage register
после проверки правил формирования outcome и фактических дат в аналитической
выгрузке. В частности, поля termination, Zero Balance, последующих
модификаций и post-event расходов не будут автоматически признаны
допустимыми признаками.

## 3. Хранение, manifest и контроль входных файлов

Создана структура `data/raw/`, `data/interim/`, `data/processed/`,
`data/manifests/`, `docs/sources/`, `reports/`, `src/` и `tests/`. Raw-файлы
не изменяются. Для каждого источника manifest хранит URL, релиз, размер,
SHA-256 и число строк. Исходные файлы исключены из Git через `.gitignore`,
чтобы не распространять данные, на которые могут распространяться условия
использования Freddie Mac.

Проверен опубликованный архив `release-47-sample-files.zip`. Он корректен как
пример файловой схемы: origination-файл содержит 1 000 строк по 31 полю, а
performance-файл — 1 011 строк по 35 полям; в обоих файлах не обнаружены
строки с неверным числом полей и дубликаты соответствующих ключей. Однако
между файлами обнаружено ноль общих loan ID: 1 000 идентификаторов в
origination-файле и 12 в performance-файле. Следовательно, этот архив не
является связанной аналитической выборкой и не используется для построения
loan-month panel или для оценки моделей.

Полный QA-результат сохранён в
[`reports/release_47_example_file_validation.json`](../../reports/release_47_example_file_validation.json),
а происхождение файлов — в
[`data/manifests/data_manifest.csv`](../../data/manifests/data_manifest.csv).

## Следующее действие

Для продолжения требуется поместить в `data/raw/` пару связанных файлов одного
vintage: `sample_orig_YYYY.txt` и `sample_perf_YYYY.txt` либо полные
`orig_YYYYQn.txt` и `perf_YYYYQn.txt`, полученные через Clarity. После этого
будут выполнены проверка связности, очистка и построение monthly panel.
