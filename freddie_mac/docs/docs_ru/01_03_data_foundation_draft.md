# Этапы 1–3. Основа датасета

**Статус: draft.** Текст будет финализирован после выполнения этапов на
фактически загруженных файлах Freddie Mac.

## 1. Определение дизайна датасета

### 1.1. Единица наблюдения и исследуемая совокупность

В настоящем исследовании объектом анализа является отдельный ипотечный кредит,
приобретённый или гарантированный Freddie Mac в сегменте односемейного жилья
США. Исследование не рассматривает универсальный профиль физического лица или
совокупность всех его кредитных обязательств. Следовательно, выводы относятся к
риску ухудшения качества конкретной ипотечной кредитной экспозиции, а не к
кредитоспособности заёмщика в целом.

Для решения задачи раннего предупреждения формируется продольный набор данных
на уровне «кредит–месяц наблюдения» (`loan_id × observation_month`). Каждая
строка соответствует состоянию одного кредита на дату наблюдения `t`, а
признаки включают только информацию, доступную не позднее этой даты.

### 1.2. Временной горизонт прогнозирования

В исследовании будут рассмотрены горизонты раннего предупреждения в три и шесть
месяцев. Для кредита `i`, наблюдаемого в месяце `t`, задача состоит в оценке
вероятности ухудшения в интервале `(t, t+h]`, где `h ∈ {3, 6}`. Конкретные
периоды, vintages и правила включения наблюдений будут зафиксированы по итогам
анализа доступных файлов.

### 1.3. Воспроизводимость дизайна

Период исследования, включённые vintages, правила исключения, горизонты
прогнозирования и определения целевых событий фиксируются до построения
моделей. Изменение любого из этих решений требует новой версии датасета и
документированного обоснования.

## 2. Документация и словарь данных

### 2.1. Формирование словаря данных

Словарь данных формируется по официальному руководству Freddie Mac,
применимому к использованному релизу. Поля классифицируются как характеристики
на момент выдачи кредита, ежемесячные показатели обслуживания, сведения о
прекращении кредита и технические идентификаторы.

Для каждой переменной будут указаны исходное и стандартизированное названия,
тип данных, экономическая интерпретация, допустимые значения, правила обработки
пропусков, источник и дата доступности.

### 2.2. Принцип доступности информации

Origination-переменные считаются известными на момент выдачи кредита. Monthly
performance-переменные могут использоваться только при подтверждении, что они
отражают состояние кредита в момент `t`. Поля, содержащие будущую просрочку,
прекращение кредита, последующую модификацию или иные post-event сведения, не
включаются в набор предикторов.

## 3. Хранение данных и воспроизводимость

### 3.1. Архитектура хранения

Исходные файлы будут храниться без изменений в `data/raw/`; очищенные
промежуточные таблицы — в `data/interim/`; итоговые аналитические наборы — в
`data/processed/`. Такое разделение позволяет воспроизвести преобразования от
первичного источника до готовой выборки.

### 3.2. Происхождение и версии данных

Для каждого файла ведётся manifest с источником, датой загрузки, версией релиза,
периодом покрытия, именем, размером, контрольной суммой и числом строк. Любое
изменение правил обработки приводит к выпуску новой версии датасета, а не к
перезаписи предыдущего результата.
